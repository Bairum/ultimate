Keep epics and tasks in a durable conversation ledger, with open work visible in the prompt.

The `plan` tool creates epics (`E1`) and tasks (`E1.1`), updates them, adds timestamped task notes, and reads full plans with `show`. Epic bodies hold Request, Selected approach, Intent, Scope (in/out), binary Acceptance criteria, Implementation, Verification, and Risks. Task descriptions hold Outcome, Scope, Non-goals, Files, Acceptance criteria with a verification command, and Constraints.

`ultimate.plan` is an exported conversation document with rewindable history and `asOf` forks (Pi Durable requires rewindable history for historical forks). Each call first saves a receipt identity via `api.memo` (namespaced by codemode for nested calls), then commits its receipt alongside the edit in a task-scoped document and saves the result via `api.memo`. Calls sharing an outer task ID have distinct receipts; interrupted replays cannot duplicate tasks or notes. Unknown keys, invalid statuses, and fields meant for the other kind of record are errors. Dependencies must name existing tasks. Notes belong to tasks; epics and tasks both accept evidence or conclusions in `verdict`. `body` remains epic-only.

The `plan` section lists non-done epics and their tasks, including dependencies and linked child conversation numbers, without plan bodies. Children resolve conversation ownership up to the root coordinator: `show` reads that coordinator's ledger, while mutations fail with “Only conversation N edits this plan; report to it instead”. The coordinator links a child explicitly with `update {key, child}`. The compact prompt section remains local to the conversation.

`web.tsx` registers the `ultimate.plan` renderer for the Documents tab (`extensions/documents`), live from the shown conversation's document: each epic's status and title with its plan folded below (open epics first) and the verdict when there is one; each task's key, title, status, role, and dependencies (done ones green), the linked child as "open #id", the verdict when present, and the last note, with the description and all notes on click. A task whose child has a worktree isolate shows its branch, state, and commits ahead, with Land through the `workspaces` actions; it refetches when the child or parent settles and on window focus, and hides Land once a landed branch has nothing new. A subagent's empty plan points back to its parent, where plans live. `plan` calls render as a compact card naming the action and key, with the plan, task, verdict, or note text below.
