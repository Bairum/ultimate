The line under the composer (`composer.status`) shows the conversation's cwd/workspace and git branch, `↑input ↓output R cacheRead W cacheWrite`, cache hit rate, cost (`(sub)` on a subscription), and context use of the model's window (warning above 70 %, error above 90 %). Hover for per-model/tool usage and context details. The models extension's composer toolbar shows the model and thinking level.

The bottom status bar is global: model output tokens per second across all conversations over the last 30 seconds, a live running-agent count including subagents (visible at zero), project-wide settled input/output tokens and cost, and the server connection with its generation. Hover the rate for input and cache rates. Provider reports may arrive late, and tool usage is excluded from rates but included in spend. Other extensions contribute the build.

Hovering a stored message shows its context and cost on its action row (`messageDetails`): a response's context as a share of its model's window and its cost; the last response of a turn adds its model, the turn's duration since the input, and the cost of every response in the turn; an input shows the context it was sent into. The tooltip breaks down the response, the turn, the context, and the model with its thinking level. A turn whose input is not loaded yet shows the response alone. `turns.ts` holds these transcript helpers.

Conversation totals come from `pi.usage`, the model from `pi.agent`, the context window from `GET /api/models`, and cwd, branch, and process from system info. The context and totals helpers live in `context.ts`. The existing `rates` action also returns settled totals from every conversation's `UsageDoc`; it scans once on open and updates from commits, independently of the shown conversation.
