Pi's footer in the status line: cwd and git branch, `↑input ↓output R cacheRead W cacheWrite`, cache hit rate, cost (`(sub)` on a subscription), context use of the model's window (warning above 70 %, error above 90 %), model · thinking · provider, and the connection to the server with its generation.

The Tokens item also shows compact `↓123 tok/s`: rolling **provider-reported output** model tokens per second for the **entire running instance: all conversations and subagents**, including main roots, forks' own work, parallel and background agents. All work adds against one wall-clock denominator over 30 seconds (actual elapsed time during warmup). Hover for input/output/cache-read/cache-write rates and scope. Existing totals, cache hit, cost and context remain shown-conversation-local and unchanged.

On harness open the server atomically scans conversation identities and seeds numeric counters from `pi.usage.models` plus `pi.live.generation.message.usage`. It subscribes to public complete commit publications at that same commit boundary, retaining only numeric settled/partial counters, never messages or content. A single server timer samples the aggregate every second, even with no browser connected. New conversations start at zero, so all their first spend counts, without late-child discovery omissions. Pi initializes fork usage rather than copying inherited usage. Tool buckets are excluded; reasoning is not added to provider output again. There are no transcript scans or Session APIs.

The server excludes historical tokens before its initial observation (or extension reload/reopen). Signed aggregate differences preserve downward partial corrections; only displayed rates clamp to zero. Settled usage and removal of its partial are adopted from the whole atomic publication before sampling, preventing double-counting. The window edge interpolates between numeric samples, not provider events. Usage reporting can arrive late (often at completion), so this is not instantaneous decoding speed. Warmup/unavailable shows `↓? tok/s`, not a fabricated zero. Sampling gaps over five seconds rebaseline; collector failures leave rates unavailable until reopen/reload. Closing the collector cancels its timer and commit subscription.

The read-only action returns the same latest server sample to every client, regardless of shown conversation. Browsers poll serially one second after each completed request; navigation and remount do not reset the server average. Disconnects, errors and generation changes show unavailable until a fresh snapshot arrives. Client timers and requests are cancelled on cleanup; stale responses are ignored.

Conversation totals come from `pi.usage`, the model and thinking level from `pi.agent`, the context window from `GET /api/models`, and cwd, branch, and process from system info. Hover an item for details; clicking the model runs the `model.pick` command when an extension provides it.
