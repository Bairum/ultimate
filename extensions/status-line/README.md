The line under the composer (`composer.status`) shows the conversation's cwd/workspace and git branch, `↑input ↓output R cacheRead W cacheWrite`, cache hit rate, cost (`(sub)` on a subscription), and context use of the model's window (warning above 70 %, error above 90 %). Hover for per-model/tool usage and context details. The models extension's composer toolbar shows the model and thinking level.

The bottom status bar is global: model output tokens per second across all conversations over the last 30 seconds, a live running-agent count including subagents (visible at zero), project-wide settled input/output tokens and cost, and the server connection with its generation. Hover the rate for input and cache rates. Provider reports may arrive late, and tool usage is excluded from rates but included in spend. Other extensions contribute the clock and build.

Conversation totals come from `pi.usage`, the model from `pi.agent`, the context window from `GET /api/models`, and cwd, branch, and process from system info. The context and totals helpers live in `context.ts`, shared with the canvas feed so both count alike. The existing `rates` action also returns settled totals from every conversation's `UsageDoc`; it scans once on open and updates from commits, independently of the shown conversation or Canvas.
