The Tokens item also shows compact `↓123 tok/s`: rolling **provider-reported output** model tokens per second over 30 seconds (actual elapsed time during warmup). Hover for input/output/cache-read/cache-write rates and scope. It includes the shown conversation and its owned descendants, including idle, parallel and background agents; parallel work adds against the same wall-clock denominator. Ownerless forks and unrelated roots are excluded. Existing totals, cache hit, cost and context remain conversation-local and unchanged.

An extension-local action selects the ownership subtree from host summaries, validates ownership records, then reads every member's `pi.usage.models` plus `pi.live.generation.message.usage` in **one atomic harness commit**. Pi settles usage and removes the partial in the same commit, so settlement is not counted twice. Tool buckets are excluded from speed; reasoning is not added to provider output again. No transcript scans are used.

The browser polls one second after each completed request, even when idle. First observation and newly discovered members establish baselines: **all tokens before that member's observation are omitted**, including output a new child produced before discovery. Signed differences preserve downward partial corrections; only displayed rates clamp to zero. The window edge interpolates between numeric observations, not provider events. Usage reporting can arrive late (often at completion), so this is not instantaneous decoding speed. Warmup/unavailable shows `↓? tok/s`, not a fabricated zero. Scope changes, disconnect/reconnect, server generation changes, errors, and sampling gaps over five seconds rebaseline. Poll timers and requests are cancelled on cleanup; stale results are ignored.

Usage comes from the conversation's `pi.usage` document, the model and thinking level from `pi.agent`, the context window from `GET /api/models`, and cwd, branch, and process from system info.
