Delegate bounded work with `subagent`: `start {agent, task, background?, fork?}`, `message {id, text, steer?}` (steers a busy child unless `steer: false` queues a follow-up), `wait {id}`, `stop {id}`, and `list`. Every new child belongs to an independent background anchor. Foreground is a waiting style, not lifetime ownership: foreground start/message and explicit wait return the answer when ready, or yield on queued steering while the child keeps running. Stopping the parent does not stop these children; use `stop {id}` explicitly. Stop cancels the captured current work and existing pending reporters/inputs, even before a child run starts; replay leaves later reuse alone. Undelivered answers steer the current run at its next tool-round boundary, or start a run when the parent is idle. Child IDs are conversation IDs. Definitions are reread on every start; children receive `subagent` and its extension only when their definition explicitly includes `subagent` in `tools`.

## Interruptible waits and delivery

A wait can yield to steering while the child keeps running. It returns status text and the child's ID, not an answer.
Message or stop that ID, or wait again. Follow-ups do not wake waits; steering and other children's answers do.
An answer already completed by the awaited child takes precedence. Only the local wait is cancelled.
Before each request, a reminder lists running children and inputs waiting to start.
Each start or message creates a reporter that delivers its answer once, including after restart.
If a child ends unanswered with `model_error` or `no_model`, the reporter waits 20 seconds on a durable deadline, then asks it to continue once before reporting failure. The retry request ID is shared by inputs from the failed run and survives restart: it uses the failed assistant entry for `model_error`, or the failed generation task for `no_model` (which has no assistant entry). Explicit stop cancels delayed, queued or active recovery along with the original inputs; aborted runs and other failure reasons are not retried.
A turn with no text, or one that stopped as `aborted` or `error`, is not an answer: a stopped Claude Code turn keeps only an empty thinking block. The reporter sends `[subagent <id> failed: ended its turn without an answer]`, and foreground answers and `wait` return `Subagent <id> ended its turn without an answer. Message it to continue.`, so the parent knows to nudge it. Nothing retries automatically, because the stop came from a person or a stop.
If the last action failed, or its input was aborted in the child's own conversation (a person pressing stop there; a parent `stop` aborts the reporter first and stays silent), a later non-reporter input that produces an answer (for example, a user typing `continue` in the child) is delivered as a normal report. Committed submission receipts are observed live and scanned on reopen; creating the reporter and recording the answer ID is atomic, so restart cannot lose or duplicate this delivery. Reporter-sent inputs remain owned by their original reporters.
Foreground, wait, and asynchronous answers include `Returned model: provider/model` from the stored assistant message (or `unknown` when unavailable), not the configured profile or self-report. Asynchronous model-facing report prefixes remain unchanged. Successful tool answers carry `details.answerId`; completed codemode scripts list these in `details.subagentAnswers`.
The backend removes queued reports already returned by those tools. Failed or yielded scripts leave reports queued.
Reports already sent to the model stay there. An explicit `wait` can still return an earlier answer.

Definitions are Markdown with YAML frontmatter, parsed by Pi's `parseFrontmatter`: required `name` and `description`, optional `resident` (boolean), `isolate` (`none` or `worktree`), `model` (Pi's `resolveCliModel` accepts `provider/id`, fuzzy id or name, and a `:thinking` suffix; unknown models are errors and custom models must be registered in Pi's `models.json`), `thinking` (a Pi thinking level), `tools` (a YAML list, `[read, bash]` or one `- item` per line), and `onFailure` (`diagnose` or `fix`, read only by the `lander` definition; see the workspaces README); other fields are errors. An explicit `thinking` field overrides the model suffix. The body is the instructions. `agents.ts` reads them from three directories, later overriding by name: `agents/` in Ultimate's clone, `~/.ultimate/agents/`, and the project root's `.ultimate/agents/` (not a conversation's cwd). Omitted tools inherit the parent's tools minus `subagent` and exclude the subagents extension. Explicit tools must remain a subset of the parent's tools; `[read, bash, subagent]` opts into bounded child delegation. Delegating children follow their assigned role, not the root coordinator's epic/worker flow. Each parent owns only its direct children, and forked children start with a fresh child index. The existing definition editor's tools checklist includes `subagent`. Tool restrictions select tools, not a shell sandbox: read-only agents' bash restrictions are instructions. An edited definition is not a code change, so it does not change the build id.

The built-in `coordinator` definition supplies instructions for Board `branch` calls: these are feature branches, not subagents, and keep their normal tools and model.

## Standing agents and owned tools

Set `resident: true` (a boolean) to make a definition available as a standing agent. The config view's Standing agent switch saves this field. Its standing conversation is ownerless, uses the project directory regardless of `isolate`, and is pinned with the lander as `@name`.

Other extensions look up `host.use<SubagentsService>('subagents')` (type exported from `server.ts`). `residents(ctx)` reads the effective resident definitions fresh and returns `{name, description}[]`. `standing(name, ctx)` creates or returns its conversation ID and configures it from the current definition on top of the root conversation's agent on every call. A new standing conversation starts on the root's model and thinking level; afterwards it keeps the ones chosen in it, and a refresh changes them only where the definition pins `model` or `thinking` (a pin applies on every refresh, so to choose freely, leave it out of the definition). Unknown and non-resident names fail with the available names. Creation and indexing are atomic; deleted conversations are recreated. The exported `Standing` document, kind `ultimate.standing-agents`, holds `{ [name]: conversationId }` on `ROOT_CONVERSATION_ID`. The `standing {name}` action opens the same standing conversation and returns its ID.

A deferred tool explicitly named in a definition's `tools` is loaded into that conversation's `modelTools.add`. This applies to children, automation profiles and standing agents; other conversations, including the root, do not gain it. Tools remain restricted to the base agent's enabled tools. Deferred tools are not a security boundary: nested tool calls can still reach enabled tools.

## Attributed transcript messages

Ordinary human input uses the core renderer. Typed agent instructions and asynchronous reports use compact Markdown cards with a bot marker, sender conversation ID, and a Source button. Long messages have a scrollable compact view and an explicit expansion control. Successful foreground answers still use the existing `SubagentCall` / `MessageResponse` renderer; their Open button now targets the answer when available.

Instructions and reports are stored as `subagents.instruction` and `subagents.report` input entries. Their data carries the sender, source entry, agent name, display body and report failure flag; the model still receives the original user message. Cards read that data directly, including through history forks and reopen. Old plain user messages remain plain messages. If a source entry is no longer in its active transcript, Source still opens the conversation without scrolling to a different entry.

Source and foreground Open offer a header Return button back to the receiving conversation and its message when known. Transcript entry anchors and the core `ultimate:reveal-entry {conversationId, entryId}` web event cancel auto-follow before revealing a row, so a long answer cannot pull the view back to its end. This one-hop navigation is local to the browser session; ordinary conversation switching remains unchanged. Missing sender summaries keep the ID visible and disable Source with an explanatory tooltip.

### Token-free preview

Start a faux instance, accept its project setup, send `delegate to worker`, and use the foreground card's Open button to inspect the attributed child instruction.

## Queued agent inputs

Above the composer, actual pending instructions and reports use quiet bordered rows: sender, instruction/report, steer/follow-up, a truncated preview with full text in its tooltip, Source, and the existing cancellation button. Human lookalikes remain ordinary queue rows. Rows read the typed input from `item.entry`; delivered or cancelled inputs leave the inbox. Source uses the same one-hop Return navigation, returning to the receiving conversation without a transcript entry target.

## Definitions are shared profiles

A definition is the profile both subagents and automations run with: one helper, `createChild` (`children.ts`) with `definitionAgent` (`agents.ts`), turns it into a child's agent configuration for `start` and for an automation that names it. Edit one in the Agents tab or as its file; both are the same Markdown, and Ultimate changes one when asked by editing that file (codemode's `ultimate.agents()` lists every definition with its source, path, and fields). Built-ins in the clone are never written: saving one writes an override with the same name to the project's `.ultimate/agents/` (shared with the team, and only once the project's setup is local) or to `~/.ultimate/agents/`. Deleting an override makes the definition it shadowed apply again.

Click a definition in the Agents tab, or New, for its config view: description, model (picked from the models extension's catalogue, or inherited from the main conversation), thinking (the levels that model supports, or inherited), tools (a checklist of the main conversation's tools, or all of them), isolate, on failure (for `lander`, or a definition that sets it), and the instructions as Markdown with a preview and the saved file. The header shows its source and path, the footer where Save writes and whether that overrides or is shadowed by another file. Duplicate starts a new definition from the shown one. Save writes nothing when the result fails to parse, and shows why inline; files that fail to parse stay listed with their errors and open with the error above the form. Another extension opens a definition's config over the web bus with `events.emit('subagents:open-definition', { name })` (`''` for a new one); `subagents:definition-closed { name }` follows when that dialog closes, so the opener can refetch and take focus back.

## Coordinator flow

The extension's prompt section makes the parent the coordinator; without this extension, that steering is absent. Do quick fixes and simple questions directly. For substantive work, inspect the code, recommend one approach (and wait for the user's go when they asked a question rather than gave an instruction), and ask only for decisions affecting behaviour or scope. Use the `plan` tool to write an epic with binary acceptance criteria and one self-contained task per unit of work; link children and record dependencies and status.

Delegate implementation to `worker` in worktree isolates. Use background children for independent work; children touching the same files run sequentially. Read reports and inspect diffs; rerun checks only for missing or thin evidence, reported failures, changes crossing workers, `server/` or `shared/` changes, or surprises. Land workers into the coordinator's checkout, then `workspace submit`: the lander runs every configured check on the merged result and reports back. Restart required Ultimate core changes only when authorized. Discard clean isolates only when requested. Record evidence yourself; a child's report is not your verification.

When all tasks are done, start one `reviewer` with the explicit immutable `base..head` commit range, never merely a directory, and the acceptance criteria; it returns one verdict, and the coordinator never starts several reviewers itself. Verify findings yourself, route confirmed fixes back by message or a new task, and verify, land, and review fixes. Post the epic verdict and report to the user. Never delegate judgment. Children never push; the coordinator never pushes, merges to remotes, or ships unless asked.

### Review team

The shipped `reviewer` reviews alone on the parent's model. For a team, override `reviewer` with a lead that lists `subagent` in `tools` and starts every `reviewer-*` definition in parallel, like this repository's `.ultimate/agents/reviewer.md`: a Luna lead that only relays and merges. Leaves need tools within the lead's. Add a reviewer by copying a `reviewer-*` file under a new `reviewer-<name>` with another model; definitions are reread on every start, so no restart is needed.

## History forks

`start {agent, task, fork: true}` gives the child the parent's visible history up to the entry before the assistant message containing this call, excluding the pending call itself. The task text is still the child's first new input. Foreground/background waiting style, independent ownership, definition instructions, model, thinking, tools (`subagent` and its extension only with explicit definition opt-in, still subject to the parent tool subset), and isolates work exactly as for a fresh child.

A fork sends the parent's context and therefore costs more than a fresh child; the prompt cache usually covers the shared prefix. Conversation documents follow their declared fork policy: `pi.agent`, `codemode.store`, and `ultimate.ui` copy `asOf` the fork entry; `ultimate.subagents`, `ultimate.metadata`, `models.login`, and Pi's inbox, live state and usage start `initial`. No built-in conversation document uses `current`. The child agent configuration is then replaced with the current parent's configuration and definition overrides; metadata is set to the child's name/task. The child's `ultimate.ui` copy is left as-is: the web reads only the root conversation's UI document, so the unused child copy cannot affect the Agents tab. Its Subagents index starts empty. Codemode's stored values remain available as of the fork point.

## Isolates

An isolate is where a child's tools run, separate from the parent. The workspaces extension owns its checkout and its record in the root `ultimate.workspaces` document. There are no sandboxes, containers or remote machines.

`start {agent, task, isolate?: "none" | "worktree"}` overrides the definition's isolate. The default is none (the parent directory); the shipped worker uses worktree. Preparation creates `<home>/worktrees/<child id>` from the parent's committed HEAD. The child's cwd and instructions point there; its first request waits for setup. The child and checkout are reused on replay.

Optional project `.ultimate/settings.json` configuration:

```json
{ "isolates": { "worktree": { "setup": ["pnpm install --frozen-lockfile --prefer-offline"] } } }
```

Commands run in order with `sh -c`, closed stdin and a two-minute timeout. `ULTIMATE_SOURCE` is the parent checkout path. Interrupted setup repeats, so commands must be safe to repeat. Failure keeps the output tail and removes only a clean checkout; dirty output stays. Failed or removed workspaces block tool calls with an explanation, which the child's answer can report to its parent.

Verify the child's commits, then `land {id}` fast-forwards its saved source branch. Both checkouts must be clean, and the child must have no live run or queued input. If the target changed or diverged, update the workspace onto it and verify again; landing never rebases or pushes. An integrated tip is a no-op. Results list commits and paths and report whether the running Ultimate clone needs restart. `discard {id}` removes only a clean, idle checkout and keeps its branch. See [workspaces](../workspaces/README.md).

Isolation is by working directory, not a sandbox: absolute paths can still reach other checkouts. Children are instructed to work only in their isolate, commit clearly, and never push. There are no remote operations or cross-process landing locks.

The shipped definitions inherit the active provider/model. No universally cheaper model is known across providers, so no model is hardcoded. Override locally to select an available fast model.

The extension document `ultimate.subagents` holds the ownership/action index. Each child gets the core's `ultimate.metadata` (`host.metadata`) with `label` set to its definition's name and `title` to its task, which the shell's header, breadcrumb, and window title show. Reporter request IDs and answer receipts prevent duplicate delivery across restarts; stop records its target run so a replay cannot abort a later run. The action `definitions` returns the definitions (without instructions), the files that failed to parse with their errors, the main conversation's model, thinking level and tools, the user and project folders, and whether the project's setup is local. `definition {name}` returns the definition that applies, its source, path and raw file, the scopes with a file of that name, and a later file of that name that fails to parse. `saveDefinition {name, scope: "project" | "user", frontmatter: {description, model?, thinking?, tools?, isolate?, resident?, onFailure?}, instructions, create?}` validates the file as discovery reads it and writes it atomically (`create` refuses an existing name); `deleteDefinition {name, scope}` removes a user or project file.

`web.tsx` renders each `subagent` call (agent, task or message, the child's workspace branch and state from the root workspace document, whether the child is working, its plan task as the plan's `TaskChip` (also on report and instruction cards), its answer, and "open #id" to show the child; the result's details say whether the child is in the background) and adds the right panel's Agents tab, which lists the agent definitions with their model and thinking level, and invalid files with their errors, refetched when the window regains focus and when the config dialog closes; each opens its config view (`definitions.tsx`, `fields.tsx`). Showing a child makes the composer steer, follow up, and stop that child; the header leads back to main.
