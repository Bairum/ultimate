Run an on-demand isolated second Ultimate before applying core changes to the shared host. Start it, check its API and UI with browser tools, then stop it. Creating a conversation never starts a preview automatically.

`instance` supports start, stop, logs and list. For an isolated calling conversation, start runs that authoritative workspace as both Ultimate source and project. A shared caller still runs the host's Ultimate source and project. `start { subagent: <child id> }` selects a child owned by the calling conversation, using the same core workspace capability. Only active, ready workspaces are accepted; pending/failed preparation, discarded workspaces and overlapping lifecycle operations are refused. Workspace previews hold a core lease that excludes land/discard until stop or child exit. Startup and abort failures also release the lease.

Start allocates a temporary home unless a separate home is supplied. Homes are canonicalized, so symlink aliases cannot reuse the host home or another starting/running preview's home. Each preview has separate SQLite storage and per-home Vite cache. The child binds directly to localhost port zero; the tool reads its existing `Ultimate: <actual URL>` stdout readiness line and checks `/api/models` while the owned process is alive. There is no free-port probe/reservation gap. Startup has a 60-second deadline and errors include the combined output tail.

Workspace previews require `server/main.ts` (Ultimate) and `node_modules` (run `pnpm install`). Project trust decisions are not added or copied: a worktree's `.ultimate/` remains gated by the user's existing decision for that path. Set `faux: true` for token-free testing; otherwise previews use real models, even when the parent uses faux. No main state or pending work is copied. Pi Durable's public abort API runs task abort protocols rather than inertly terminalizing a copied database, while submitting or waiting starts its scheduler; copying pending work is therefore not offered.

Logs returns the last 200 lines; list shows running process-local instances. At most three instances may run, including starts in progress; all are stopped during host shutdown. Homes and logs are not durable instance registrations. Temporary homes remain available for inspecting artifacts. The tool is not replay-safe. Never point a preview at another storage owner's home; returned URLs can be passed directly to screenshot or browser.

`web.tsx` renders each `instance` call: a started instance as a card with its URL as a link, pid, and home; `list` as one card per running instance; `logs` collapsible.
