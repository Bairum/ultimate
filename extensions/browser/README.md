Look at Ultimate's UI and drive fresh headless Chromium pages with `screenshot` and `browser`. After UI changes, inspect the returned image rather than assuming the page renders.

Install Chromium separately; playwright-core does not download browsers. Resolution checks `ULTIMATE_CHROMIUM`, `/usr/bin/chromium`, `/usr/bin/google-chrome-stable`, then `~/.cache/ms-playwright/chromium-*/chrome-linux64/chrome`. A browser is launched lazily and closed when the host shuts down. Each call has its own isolated context, closed on completion or cancellation.

No call can hang: loading, each step (including `eval`, which Playwright never times out) and the capture each time out after 30 s (`timeoutMs` overrides it), and a whole call after four such limits plus its explicit waits. A timed-out step fails the call with a `TimeoutError` on its `Step n:` line. Closing a context is bounded too; a context that will not close (a wedged renderer) closes the shared browser, so the next call launches a fresh one.

`screenshot` accepts url, path, viewport dimensions (1440 × 900 by default), selector, fullPage, waitMs (1500 by default) and light/dark theme. For own-UI screenshots, theme initializes this isolated browser's `ultimate.theme` localStorage preference before navigation; it never changes durable UI state. Other URLs receive only the browser color-scheme preference. `url` is the page to load; a relative one such as `/?conversation=1` resolves against this UI. `path` is where the full-resolution PNG is saved: it must end in `.png`, resolves against the conversation's cwd (its worktree in an isolated workspace), and missing parent directories are created. Without it the PNG goes to `$ULTIMATE_HOME/screenshots`. Either way the result names the absolute file; Pi's `resizeImage` returns compact PNG or JPEG images capped at 1600 pixels on the longest side, using its default quality and byte limit. Resized images include a dimension note for mapping coordinates to the original. If an image cannot fit the limit, the tool returns the PNG path without an inline image. Loading console and page errors accompany the title and PNG path.

`browser` accepts the same url and path, click/fill/press/wait/eval steps and an optional final screenshot (default true). JavaScript eval runs inside the page. Calls stream progress; screenshot is replay-safe, browser is not because interactions may submit prompts. Both are automatically available in codemode's `tools`; use `const shot = await tools.screenshot({}); if (shot.image) image(shot.image)` to display its image. Structured nested results include title, PNG file path, outcomes, and an image data URI.

`web.tsx` renders `screenshot` as a thumbnail that opens full size, with the page title, PNG path, and loading errors, and `browser` as its steps with an outcome each (✓, ✗ with the error, the value an `eval` returned) and the final screenshot.
