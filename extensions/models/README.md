Model, thinking, and login, as Pi does them: a model button and a thinking-level button in the composer toolbar, a searchable model picker grouped by provider (availability, login status, context window, thinking, price per million tokens), and a login dialog that drives any pi-ai provider's flow, subscription or API key, with credentials shared with pi in `~/.pi/agent/auth.json`.

Picking a model calls `api.configure({ model })`; the server keeps the thinking level when the model supports it and otherwise clamps it with Pi's `clampThinkingLevel`, and the toolbar shows what it configured. A model whose provider is not logged in opens the login for that provider. The thinking menu offers the model's supported levels (Pi's `getSupportedThinkingLevels`), and Shift+Tab cycles them in Pi's order, like Pi. Commands: `model.pick`, `model.thinking`, `model.thinking.cycle` (Shift+Tab), `auth.login`; the status line's model opens the picker through `model.pick`.

Login is this extension's own: `server.ts` runs Pi's `modelRuntime.login` behind four actions, `login { provider, type }` → `{ flowId }`, `answer { flowId, value }` (an empty answer is an answer), `cancel { flowId }`, and `logout { provider }`. Each flow is shown in `models.login`, a document on the conversation that started it: status, the pending prompt, and the provider's events, never answers, credentials, or provider error details (a failed flow reads `Login failed`). Flows are process-local; one that dies with its process reads cancelled from the next start on. The dialog streams the document with `useDoc` and renders the events (`auth_url` with open and copy, `device_code` with a countdown, `info`, `progress`) and the `text`, `secret`, `select`, and `manual_code` prompts; closing it or the tab cancels a running flow, configured providers can log out, and a finished login or logout refreshes the model list with `refreshModels()`.

`picker.tsx` is the model picker, `login.tsx` the login dialog, `state.tsx` the shared helpers (the current model, cycling, dialog ids, which provider the login opens on), `server.ts` the login actions and document.
