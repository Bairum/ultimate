# Context replay

Read-only, offline analysis of this project's stored assistant usage and context messages. **No model calls, no tokens spent, no POST/PUT, no agent actions.** The only network requests are GETs to `/api/events` (read the initial `conversations` SSE frame and immediately cancel), `/api/models`, and paginated `/api/conversations/<id>/history?before=<cursor>`. Redirects are rejected. `/api/conversations` is a **POST creation** endpoint, not a GET listing endpoint in this version.

```sh
node .ultimate/bench/context-replay/replay.ts
node .ultimate/bench/context-replay/replay.ts --conversations 50,19996 --json
node .ultimate/bench/context-replay/replay.ts --base http://127.0.0.1:4747 --ttl 5 --rewrite 20000
node --test .ultimate/bench/context-replay/*.test.ts
pnpm exec tsc -p .ultimate/bench/context-replay/tsconfig.json
```

`--ttl` is minutes; `--rewrite` is the strict cache-write token threshold. `--json` includes individual rewrite records with conversation/entry IDs, gap, changed section keys, full remove/re-add detection, block distance and write cost. `--keep` retains fetched JSON in a printed OS temporary directory; otherwise it is deleted even on failure. Temp files contain private conversation history: do not share them. Nothing is written in the repository or the host's history/output stores. A live host can advance while pages are fetched; each conversation is bounded by its first page, not one global atomic snapshot.

## What is measured

- Recorded `pi.assistant` usage is the actual-spend baseline, including non-Anthropic requests. Projections apply only to Anthropic requests (`anthropic-messages`, `anthropic`, or `claude-code`). These are stored retail usage costs, **not invoices**; subscription billing may differ.
- Fork-inherited requests are context only, not billed twice. Entry IDs identify the originating conversation; only its own responses contribute spend. History is replayed oldest-first, respecting reset/compaction heads and omit/replace edits. Head changes drop projected ledgers; retained results may be considered again in the new context. Failed/aborted/deferred assistant messages do not contribute context.
- A rewrite is `usage.cacheWrite > --rewrite`. First matching attribution wins: first own request or no previous assistant, idle TTL, head change, model/thinking switch, changed system sections, tool-list change, historical hygiene (zero: it was off), more than 20 block positions, unexplained. Changes in provider/model/thinking are inferred from successive recorded assistant messages; Pi stores agent configuration as the `pi.agent` document, not separate model/thinking entry kinds. A reset after an existing response remains a head-change candidate even though its context is new. TTL wins over a simultaneous head change, as requested.
- Positions count consecutive tool-use blocks as one and consecutive tool-result blocks as one; other nonempty blocks count individually. The distance is the newly appended request suffix, including the preceding assistant response, not the whole transcript. Rewrites are not asserted to be complete context rewrites: a >20k write can also be ordinary large new content. Those remain unexplained when no earlier cause matches.
- Full remove/re-add means a patch nulls every currently visible section (and contains only null values), then a subsequent patch restores all those keys before the next request. Keys remain literal (e.g. `project_context`, not renamed to `docs`). Initial baselines and baselines following heads are not section churn.

## Projections and limits

Positive net means savings; negative means extra spend. Rows are **counterfactual estimates**, not measured improvements. Events mean converted requests, pings, or requests carrying shortened results, depending on row.

1. **1h cache:** every write is repriced at 2× inferred input price instead of its recorded price; >threshold writes after gaps between the configured TTL and 60 minutes become reads. Input price comes from recorded write cost (accounting for `cacheWrite1h`), otherwise input cost, otherwise the conventional 10% read ratio. Recorded read/output rates are used when available. We optimistically treat all gap-qualified writes as reusable even if another cache invalidation coincided; attribution exposes overlapping section/head changes for inspection.
2. **Keep-warm:** incremental to 1h cache, not a 55-minute ping on a 5-minute cache. For >60-minute gaps ending in >threshold writes, simulate one ping every 55 minutes. Each costs a read of the preceding context plus eight output tokens; the next rewrite becomes a read. Coordinator labels and the exact `@ultimate` title identify eligible conversations; worker/reviewer/scout labels exclude workers. System instructions can refine the role; unidentified roles have their own row. **Historical paused/failure/child-wait state is not reconstructed**: this is an optimistic upper bound for role-eligible conversations, not a prediction of the narrower shipped eligibility. No ping is projected beyond the final recorded request.
3. **Offload:** apply to shown text >16KB, except `read` and `offloadExempt` results. The private excerpt logic from `extensions/context-offload/store.ts` is **replicated exactly**: head 1900 bytes, tail 3800, matches 1400, 300 Unicode characters/line, 8192-byte final ceiling, same markers and rejection conditions. `offload()` itself is not pure: it reads spills and writes output files, so it is never called. A synthetic `/project-home/outputs/<conversation>/<call>.txt` substitutes for the host's private output path. This small path-length difference can move boundary cases either way. Hidden spill files and nested codemode results are not fetched; savings from their unseen content are underestimated. Ingestion changes have no cache rewrite penalty.
4. **Hygiene:** imports the pure `candidates`, `gateOpen`, `suffixPositions`, `placeholder`, and token estimator from `rewrite.ts`; never imports or starts its server facet. Candidate detection uses the conversation cwd. The cheap-suffix gate includes the 20-position bound with six reserved positions; pressure-only candidates protect the newest 16k tokens. Persistent decisions save on subsequent request resends; a warm-cache gate opening incurs one estimated suffix rewrite. Only visible, uniquely paired calls/results are eligible; nested codemode reads are opaque and therefore underestimated.
5. **Pressure masking:** requests exceeding 60% of their model's `/api/models` context window mask text-only, successful results ≥500 estimated tokens that lie entirely outside the newest 40k tokens. Each newly masked batch charges one suffix rewrite while warm, then saves read-priced resends. This is the requested per-result pressure scenario; it does not require the shipped 8k aggregate minimum, so small batches can overestimate masking frequency. Missing model windows disable masking and are counted. Masked-then-reread counts distinct later direct tool-call identities matching a masked path (resolved against cwd, ignoring read offsets) or exact command. It is a quality proxy, not evidence masking caused the reread; nested calls are invisible, making this a lower bound.
6. **Section churn / proposal B:** count all section text appended after the initial baseline, including the subset due to full remove/re-add, and price each append as a write followed by read-priced resends until a head change. This is a **gross upper bound**: removing every patch would lose current instructions. It does not claim a semantics-preserving patch coalescing algorithm or assign causal blame to a section merely because it changed before a TTL rewrite.

Text savings use approximately `characters / 3.5`; gate/suffix sizes use Pi's imported message estimator (including its image allowance), and hygiene candidates use their own production token estimator. Real tokenization varies in either direction. Rewritten suffixes are estimated before reduction and charged at full write price, without subtracting their displaced read cost: conservative, often overstating rewrite penalties. Read pricing even on cold resends understates gross text-removal savings. The first request carrying a removed result counts as a resend because it is an actual request that would have carried that result. System/tool conversion and missing-tool-result synthesis are not reimplemented; block/suffix estimates may differ from wire requests.

The combined row unions result savings by call ID (maximum, never sums overlapping offload/hygiene/masking), charges the larger simultaneous suffix rewrite once at 1h write price, and combines TTL, eligible warming and section-churn savings. It remains an **optimistic upper-bound combination**, not an exact joint cache simulation: TTL/section savings and removed suffix bytes can overlap; savings from reapplying gates to already shortened contexts are not simulated. Unknown-role keep-warm is excluded. Compare each separate row before using combined projected spend to judge a trial.
