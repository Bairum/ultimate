How Ultimate fits together

Five pictures, one question each. Ultimate is a web UI and a server that runs coding agents on Pi Durable; almost everything Ultimate adds lives in extensions that reload while it runs.

1The big picture

What runs where. The browser talks to one server process; a tiny supervisor keeps that process alive and swaps it on restart. Each layer reloads differently, so the conversation you are in keeps running.

2Where Pi Durable sits

Pi Durable is the engine: it stores every conversation as entries, runs every model turn and tool call as a checkpointed task, and resumes them after a crash. Ultimate is the layers on top: an extension host, and the features that make conversations into a project.

3Extensions and their interfaces

An extension is a folder. Its api.ts is what other server code may use, its refs.ts what the browser may use. Four channels connect extensions; pick one by what crosses it. Dependencies always point down.

4The event bus, followed through one landing

An event is written in the same commit as the change it describes, so it exists exactly when that change does. Each reactor keeps its own cursor and advances it inside its handler's commit. Here is what happens when a branch's work lands.

5The agent forest

Every box is a Pi Durable conversation; the roles are Ultimate's. You talk to @ultimate; it starts a branch per piece of work; branches delegate to subagents and land through the lander; landings flow back into the root's memory, which the next branch starts from.
