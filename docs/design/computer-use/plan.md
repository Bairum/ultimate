# Computer use: phased plan and decisions

Sizes: **S** ≤ 1 day of agent work and ≤400 lines; **M** 1–3 days and 400–1,500 lines; **L** more.
Every phase lands on its own and is reviewed. UI phases go through preview rounds (`ui-preview-round`).

## Decided (2026-10-25)

First round: 1a host desktop with per-app consent · 2a Cua Driver pinned (0.37.0, installed) · 4a three curated tools
(Jev goal mode lives inside `computer_act`) · **5b Jev-first for routine steps, frontier model as planner and
fallback** · 6a per-app consent granted only by the user · 7a @ultimate may grant within a hands-off goal's scope ·
8a official MCP SDK · 9a spike done ([spike.md](spike.md)).

Second round:

1. **cua's Python agent:** no side-by-side. Port its budget manager, trajectory export and argument normalisation
   ([cua-agent-loop.md](cua-agent-loop.md)).
2. **Second-level Stop:** a second Stop, or a step overrunning by 1 s, runs `cua-driver stop`. That ends every
   Driver session on this Mac, and the card says so.
3. **Display sleep:** stop the Driver daemon after 5 idle minutes.
4. **What Jev sees:** labels and non-secure values (truncated) for consented apps, plus a per-app "no Jev" switch.
5. **Jev thresholds:** conservative. Act at p ≥ 0.80 with a 0.25 margin, done at ≥ 0.85, escalate on risk ≥ 0.30.
   Tuned in phase 4.
6. **Phase order:** explicit (big-model) mode and Jev goal mode are built **together** in phase 1.
7. **Typing test:** run it. The user types in TextEdit for two minutes while the agent edits a separate region; the
   outcome is recorded in [spike.md](spike.md).
