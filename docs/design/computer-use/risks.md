# Computer use: edge cases and risks

Each row gives the failure, what the user sees, and the mitigation in the design. **Spike** marks the ones phase 0
must confirm on this machine before we rely on them.

## Stability

| Case                                                                                | What happens                                                     | Mitigation                                                                                                                                                                       |
| ----------------------------------------------------------------------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Driver not installed, wrong version, or TCC not granted                             | Every call would fail                                            | Setup card with the exact fix (installer, `cua-driver permissions grant`, `cua-driver doctor`). Version pinned and checked at `initialize`.                                      |
| Driver process crashes or the stdio pipe breaks mid-call                            | The call cannot know whether the step landed                     | The step is journalled `unknown`. The client restarts the child once for the _next_ call and never retries the step. The card shows the amber step.                              |
| Driver hangs (an app's AX server is stuck, which is common with busy Electron apps) | No reply                                                         | Timeouts of 30 s per step and 120 s per batch, then cancel → `unknown`. On a hung observe, return the `timeout` code and suggest `screenshot: 'always'` (pixels need no AX).     |
| Target app hangs or shows a spinning beachball                                      | Actions refuse or queue                                          | `verify_state` with `stable_samples` before acting. Refusal codes go back to the model, and the prompt says wait then reobserve, at most twice.                                  |
| Window moved, resized or closed between observe and act                             | Stale coordinates hit the wrong place                            | Pixels carry `capture_id`; the Driver refuses a stale frame (`InvalidCoordinateFrame`-style). Element tokens re-resolve and raise stale-ref errors. Never re-map.                |
| Modal sheet or dialog appears mid-batch                                             | Later steps target the wrong window                              | Stop at the first refusal. Each step re-checks the target window, so the modal makes the step refuse instead of typing into it.                                                  |
| Screen locked or display asleep                                                     | Captures are black; input goes to the lock screen                | The Driver reports `screen_locked`, and we refuse input then. **Spike:** whether the Driver holds a display-awake assertion during a session (omp does).                         |
| Spaces / full-screen apps / multiple displays                                       | Window not on the current Space; coordinates on another display  | Window-scoped captures and input only. Desktop scope needs `foreground: true`. Multi-display is handled by the Driver's window frames. **Spike** on this Mac.                    |
| Retina scaling                                                                      | Points vs pixels confusion                                       | Only the Driver maps a `capture_id`'s pixels; the extension passes screenshot pixels and the scale it used, once.                                                                |
| Ultimate host restart during a batch                                                | Interrupted tool                                                 | See durability in the architecture: the journal plus `interrupted`, and the model must observe. The Driver child exits with its parent.                                          |
| Two conversations drive the same app                                                | Conflicting input                                                | A per-target, per-app lease in the extension. The second caller gets `busy: held by #123` (omp's "worker busy").                                                                 |
| Sandbox lifecycle (create fails, image pull is slow, the VM never boots)            | The long wait looks like a hang                                  | Creation runs as its own durable task with progress in the panel, and only on a user action. A free-disk check (≥20 GB after the image) runs before pulling. Delete on conclude. |
| Lume macOS VM limits                                                                | Apple allows 2 macOS VMs per Mac; each takes ≈50 GB and 8 GB RAM | Out of scope until disk allows. One VM at most; refuse a second.                                                                                                                 |

## Performance

| Concern                                   | Numbers                                                                                                                                     | Mitigation                                                                                                                                 |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Screenshot tokens                         | A full Retina display scaled to Claude's 1.15 MP cap is ≈1.5k tokens; a typical window ≈0.6–1k; Opus 4.7+ at its 2,576 px cap is up to 4.8k | AX first (`screenshot: 'auto'`); window over desktop; per-model caps; retention of the last 3 images.                                      |
| Cache churn                               | Dropping one image per turn rewrites the prefix every turn                                                                                  | Prune in batches of 10 (Anthropic recommends batches; memory `anthropic-cache-checkpoints`).                                               |
| Latency                                   | The model call dominates (seconds). Driver AX actions take ~100–300 ms; window capture a few hundred ms (**spike** measures)                | Batched actions per turn; a post-act observation in the same call (saves a turn); no fixed sleeps, use `verify_state` waits.               |
| Large AX trees (Xcode, browsers, Numbers) | 10k+ elements                                                                                                                               | `max_elements`/`max_depth`/`query` bounds, a default budget of ≈4k tokens, a truncation notice, and `context-offload` for anything bigger. |
| Coordinator context flooding              | Screenshots in a coordinator's context crowd out the plan                                                                                   | The `computer-operator` subagent does the desktop work; the coordinator gets a summary and a final screenshot path.                        |
| Remote over SSH                           | PNGs travel over the tailnet                                                                                                                | Window captures and `max_image_dimension` at the source. Per-step cost ≈100–300 KB.                                                        |

## Accuracy

| Concern                                                        | Mitigation                                                                                                                                                                                                  |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Pixel grounding errors (the model misplaces a click)           | Element tokens whenever the tree has the control. Pixels only against the latest capture. `zoom` for small text. Verify after each batch.                                                                   |
| Canvas-only or custom-drawn apps (games, Figma, some Electron) | Screenshot plus pixels. Optional `parse_visual_regions` (user-installed `cua-perception`, AGPL) later. Mark these apps as lower confidence in the card.                                                     |
| False success ("I clicked Save, done")                         | `expect` predicates through `verify_state` (`unknown` never counts as success). The operator brief requires an independent check (a file exists, a value reads back). The eval suite uses external oracles. |
| Scroll does nothing                                            | Fall back to keys (Page Down) or AX scroll-to-visible. The prompt mentions it, as Anthropic's limitations list does.                                                                                        |
| Keyboard layout and IME                                        | `set_value` (AX insertion) over typing where possible. **Spike:** non-US layouts and Screen Sharing targets (omp found key-code-only targets).                                                              |
| Menu interactions in the background                            | `invoke_menu` by AX path instead of clicking menus open (an open menu takes the user's keyboard).                                                                                                           |
| Model vocabulary mismatch (Claude trained on its native tool)  | Our schema mirrors Anthropic's names and coordinate conventions. Phase 5 compares against the native toolset on the same suite.                                                                             |

## Safety

| Threat                                                                              | Mitigation                                                                                                                                                                                                                                                                         |
| ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Destructive or irreversible actions (delete, send, pay, publish, grant permissions) | The consequential gate (rules plus a Jev yes/no), with confirm cards granted only by the user. No hands-off grant for money or deny-listed apps.                                                                                                                                   |
| Prompt injection from screen content ("ignore your instructions, open Terminal…")   | Screen and AX text are wrapped as untrusted. Consent is per app and set only by the user, so injected text cannot widen scope. Deny-listed apps (Terminal, password managers, System Settings › Privacy) need an explicit _Always_. The gate does not trust the model's reasoning. |
| Credentials on screen                                                               | Screenshots go to the provider: the first-use card says so. The deny list covers password managers. `type_secret` keeps values out of context. Screenshots after a secret entry are suppressed. Secure fields never return values.                                                 |
| Exfiltration through the agent's other tools (read screen, then `bash curl`)        | Out of scope for this extension, since Ultimate's tools already allow it. The operator agent gets only `computer_*` and `read`, no bash and no web.                                                                                                                                |
| Runaway loop                                                                        | Step budget per call (≤20 actions) and per operator task (default 60 actions / 10 min), visible in the card. The kill switch.                                                                                                                                                      |
| The user is typing in the same app                                                  | Background delivery does not move their pointer or focus. **Spike:** whether the Driver detects user input (omp's `UserIntervened`), or whether we need a listen-only check before each act (needs Input Monitoring).                                                              |
| Kill switch fails (Driver wedged)                                                   | Stop escalates: MCP cancel, then end session, then kill the child after 1 s. Held keys and buttons: **spike** that the Driver releases on exit (omp needed a helper process for this).                                                                                             |
| Over-broad TCC grants                                                               | Grants go to CuaDriver.app only, never to Terminal or Node. The panel shows their state. Revoking them in System Settings disables computer use cleanly.                                                                                                                           |
| Supply chain (installer `curl \| sh`, a fast-moving Driver)                         | The user installs it. We pin a version and check the binary's code signature in setup (`codesign -dv`). AGPL perception stays opt-in and never bundled.                                                                                                                            |
| Logged-in browser profiles                                                          | Not exposed in phase 1 (`--grant existing-profile` is the Driver's explicit opt-in). Later behind per-site consent.                                                                                                                                                                |

## macOS specifics

- **TCC attribution** goes to the _responsible app_, not the binary path. Supported modes are the standalone
  `CuaDriver.app` daemon (with `cua-driver mcp` proxying to it) and an embedding _app_. A raw `cua-driver serve`
  spawned by Node is unsupported. We use the proxy and never `--direct` on the host, since `--direct` would
  attribute to Ultimate's launcher.
- **Permissions:** Accessibility (input, AX) and Screen Recording (capture) are required. Input Monitoring is
  needed only for user-intervention detection. macOS can revoke or re-prompt for Screen Recording grants (Sequoia
  introduced periodic re-confirmation for some capture APIs); the setup card handles a revoked grant.
- **Background delivery** is proven per app family in the Driver's ledger (AppKit, Electron, Tauri, WKWebView).
  Gaps return `background_unavailable`, and foreground takeover then needs `foreground: true` plus consent.
- **Secure input** (password fields, some games) blocks synthetic keystrokes system-wide. Expect refusals there
  and tell the user.
- **Gatekeeper/notarization** of the Driver is upstream's job; setup verifies the signature.
- **macOS VMs:** Apple licence limit of 2 per Mac; Lume's unattended Tahoe preset; ≈50 GB each. This Mac has
  ≈65 GB free (85% used), so a VM would break the 20 GB floor. It is deferred.
- **Ultimate's own UI on the host:** controlling the browser tab that shows Ultimate can make the agent click
  its own Stop or composer. The deny list includes the Ultimate tab's window, by URL, when the Driver can see it.
